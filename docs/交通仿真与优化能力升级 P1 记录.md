## 实现

- 分支 `codex/traffic-simulation-p1` 基于 P0 提交 `8dbc508`；P0 的草稿 PR 为 [#106](https://github.com/Ran2424/transportx-agent/pull/106)。不修改已有工作区、原模型配置或 Git 历史。
- `modules/optional/traffic-simulation`（0.1.1）：携带计算入口、唯一 TraCI 适配、服务账本、原子时间块、网络检查、Skill 与 Pi Extension。Node 作业清单与结果复核移入 `src/server/simulation-job.ts`，开发探针仅作薄适配。没有第二 Agent Loop、地图工作台或调度框架。
- `modules/optional/hongqiao-night-demo`（0.1.0）：独立 Data Module，包含可复现网络源、已生成 UTM 网络、纯道路与最小多方式场景、有效日期、合成来源说明和 SHA-256 清单。坐标仅作地图锚点，不代表虹桥实际道路、站点或运营规则。
- 四个批准 Host 工具为 `traffic_prepare_scenario`、`traffic_run`、`traffic_execution`、`traffic_query_results`。业务参数不能设置程序路径、输出目录、墙钟预算或脚本。当前产品预算为已测的 600 s、120 辆背景车、100 名旅客；超出时明确拒绝。
- 原生运行时为 SUMO/netconvert/duarouter、TraCI/sumolib 客户端与投影数据；安装及装配验证完整性清单和精确路径/版本。基础包仅保留批准工具契约，不携带可选模块的业务脚本、Skill、Extension 或 Data。
- Host 复用服务令牌、持久 Pi 会话归属、会话 Job、全局进程额度和进程树回收。Run 先持久受理并关联原工具调用，再派发；同调用不重复，unknown 保留工作区占用。取消请求、实际退出和最终结果提交分别确认。完整成果的结果清单哈希保存在 Host 私有记录中，后续读取检查索引及块哈希。
- Simulation Adapter/Renderer 使用固定 Run 引用、独立块索引与观看时间。地图共用挂载、视角和 GeoJSON 数据源操作，Geo 和 Simulation 各有地图实例、相机与选中状态。运行索引通知沿既有 WebSocket/Kernel 投影，历史不存帧。隐藏/暂停仅影响观看，不触发计算取消。
- Canvas 上下文由 Host 根据固定时刻和对象重新构造，绑定 Run、场景、Job/网络/帧哈希和实际查询结果；不采纳浏览器自报计数。尚未发布的时间和不存在的对象拒绝读取。

## 当前限制与下一阶段依赖

- P1 的三项内部里程碑按能看、能查、能恢复顺序完成；最终实际调用、固定上下文、恢复、可见延迟及资源证据见摘要。P2 依赖这些 Run、归属和块读取语义，不复建执行框架。
- 当前导入支持地理参考明确的 WGS84/UTM SUMO 网络；不在线下载 OSM，不接受外部 XML 引用或文件型投影网格。疏运模型仍为 P0 两个方向、单接驳车与单网约车的最小服务规则。
- 已有仿真输入/Run 的会话跨工作区移动暂明确拒绝，防止私有归属与工作区成果分离；原有不含 Simulation 资源的移动流程保持。工作区内历史读取不启动 Pi；服务层已实测卸载后的成果读取。真实 Electron/Host 停止并确认原进程消失、重启后 Run 清单和查询保持，Pi 数量为 0。
- 未实现多点/多车、多种子配对比较、阈值反馈和报告；它们依赖 P1 退出后才能进入 P2。
- P3 真实虹桥校准暂缓；P4 仍需目标平台干净环境、安装/恢复/卸载、完整许可与签名证据；P5 自动优化/在线控制继续后置。
