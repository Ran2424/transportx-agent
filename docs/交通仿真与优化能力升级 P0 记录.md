## 2. 代码与运行来源

P0 是 `scripts/simulation/` 中的可执行技术探针；固定合成输入位于 `test/fixtures/simulation/`。不是已安装的生产 Module，也没有修改 Module manifest。计算入口不读取 Pi、Canvas、Host token 或平台私有目录。

- `job.mjs`：业务输入白名单、可信参数转换、输入真实路径/哈希、已发布块读取、结果复核。
- `compute.py`：独立计算入口、清单校验、统一时钟、有限运行、诊断与结果候选。
- `engine.py`：唯一 TraCI 调用位置，管理道路运动、停靠、入网/离网、资源释放与退出确认。
- `model.py`：旅客、容量、班次、换乘和外部行程账本；不在 SUMO person 与 Python 两边同时扣减容量。
- `blocks.py`：完整时间块、唯一事件序列、原子索引发布；不经 stdout 传轨迹。
- `probe.mjs` / `runtime.mjs`：真实运行、失败注入、运行中读取、进程与资源测量，以及原生依赖闭包重定位。

实际使用任务指定的 Python 3.10.14，SUMO/TraCI/sumolib/sumo-data 均为 1.28.0。四个实际下载 wheel 的来源与 SHA-256 固定在 `runtime-lock.macos-arm64.json`，安装约束为带哈希的 `requirements.txt`，不修改 Conda 或系统安装。

选择直接 TraCI 路线。已检查 AgentSUMO 固定提交 `2ad1d91a02f442218d54f2b1aec25c3b813ed5df`：主项目要求 Python 3.12，独立 MCP 包允许 3.10，但 Runner 依赖全局 settings、路径工具、整场内存轨迹和额外依赖。将其改成显式作业、单一账本和增量完整块需要替换这些部分。直接入口已通过下面的实跑，不引入 MCP、第二 Agent Loop 或第二执行后端。AgentSUMO 本身未运行，源码比较不作为其运行验收或性能结论。

## 3. 四项退出证据

### 跑得起来

在 Apple M4、10 逻辑核、24 GiB、macOS arm64 上真实运行。计算环境显式替换，父进程注入的测试秘密标记和 `TAU_SESSION_TOKEN` 不进入 Python 或嵌套 SUMO。取消及 SIGKILL 引擎故障后，分别核对 Python 和 SUMO PID 已不存在，不以请求发出或外层退出码代替回收确认。

从实际二进制递归核对并复制 222 个非系统原生文件，约 343.4 MB，外部引用均解析为包内 `@loader_path` 或系统库。复制纯 Python 客户端后移动到带空格的新目录，在空环境启动 sumo/netconvert/duarouter，并使用该目录完成全部计算、取消和异常检查。

冷启动样例：sumo 32.056 s、netconvert 62.072 s、duarouter 0.482 s。此前并行回归期间的一次 netconvert 冷启动超过原草案 60 s，被 ProcessRunner 终止；同一路径后续启动为 0.541 s，另一次新复制目录为 31.525 s。原因尚未定位，不归因于未证实的系统机制。依据实测将**准备阶段**预算修订为 120 s，重新完整通过；计算作业仍为 60 s。超时必须报错，不能记成功。

这只是干净目录/空环境重定位，不是干净 OS 或最终安装器验收。wheel 声明 macOS 15 arm64；Windows 有官方 x64 来源，但本机不能提供 Windows 实跑证据。EPL/GPL 选择声明及四个包的 LICENSE/NOTICE 已保存；全部传递库的许可证清单与签名仍需 P4 审核。当前体积与冷启动是待解决的交付风险，不承诺生产包大小或启动速度。

### 算得正确

两个固定入口共用清单、生命周期、时间块和提交候选格式：

- 纯道路：3 辆计划车辆全部实际入网并到达，原始 tripinfo、事件和指标互相核对，不要求旅客/服务字段。
- 最小疏散：hub、relay、east/west 两方向，一辆公交角色接驳车、一辆网约车、有限容量末班地铁。道路车辆真实行驶和停靠；运营参数均为合成。公交 vClass 为 bus，P0 沿用默认车辆动力学参数，不代表真实公交车型已校准。

固定疏散场景的 6 人中，5 人在时域内到达，另 1 人尚未到达；5 人实际离开枢纽，2 人完成整链，3 人候接续。55 条必要事件覆盖：

1. t0 到达只计一次；t=5 旅客到达先于同刻班次分配，按稳定 ID 上车。
2. 同一公交的两个候选动作只有一个预留成功，另一动作拒绝为 `vehicle_reserved`。
3. 容量 2，首班仅接走 a/b，c 留队；车辆实际返场后才能再次接走 c/e。
4. 命令接受 t=7 与实际运动确认 t=8 分开记录；前者不算实际离站或服务完成。
5. 末班容量不足和末班已关闭分别记录；离开微观路网边界或下客不等于完成整链。
6. 无匹配旅客时拒绝发车，不中止计算；旅客、车辆与占用在每步核对互斥/守恒。
7. 仅把地铁剩余容量从 1 改为 2，网络保持不变，完成整链人数从 2 变 3。
8. 独立新 Run 将末班时刻设到已观测的换乘就绪时刻，核对等号允许上车；没有在运行中偷看未来决策。
9. 相同冻结输入/种子重跑，必要事件与指标一致。墙钟、路径、PID、文件哈希并不要求跨 Run 字节相同。

代表样例为 100 人、120 辆背景车加 2 辆服务车、600 仿真秒，峰值 44 辆活跃车。122 辆计划车核对为 74 辆入网、48 辆在 SUMO 入网队列；入网车辆中 70 辆到达、4 辆未完成。100 人核对为 2 完成、3 候接续、95 候车。这是两车道被停靠服务车约束的合成积压场景，不删减需求来制造通过。

### 边界清晰

17 组检查包括双端拒绝未知字段/执行参数覆盖、单位/缺失字段、时区/日期/跨午夜、字符串/布尔强转、种子、时域和不支持的服务组合；另检查错误 ID 映射、XML 间接引用和符号链接在启动引擎前被拒绝。

作业清单保留实际网络版本/哈希、映射版本/网络关联、业务输入、可信执行参数、计算代码版本/组合 SHA-256。仅改地铁容量复用原网络；改变道路速度后重新转换 v2 网络，生成新的网络哈希和映射引用，并真实运行。

结果复核检查请求清单哈希、预期 Run/网络/时域、所需文件与哈希、原始 tripinfo 的车辆 ID/入网/到达计数、完整索引、事件序号、末帧旅客状态及指标。另以真实空 Python 进程验证“退出 0 但无成果”不能通过，并对真实成果改字节验证拒绝读取。

取消得到 `cancelled`，清理确认独立记录；取消时原始输出可能比最后已处理步不完整，保留诊断，不覆盖取消原因，也不当正常实验。引擎 SIGKILL 得到 `simulation_result_unknown`、退出码 -9 和已确认回收，保留已发布前缀，不自动重跑。计算候选仍不是 P1 的 Host 持久提交。

### 结果可读

7 个正常 Run 均在计算完成前读取到完整块；每块重新获取索引后单独恢复，不依赖前块内存。必要事件只存一次，轨迹每 2 秒采样；未发布 `.part` 文件不进入索引，异常尾部不补零。取消保留完整尾块，故障只保留先前已发布的完整前缀。

600 秒代表样例约 2.91 s（含约 1 s TraCI 连接启动等待），分块约 4.73 MB；最大缓冲块+事件约 102 KB。参考分解：步进 0.045 s、读取/基础核对 1.300 s、路径查询 0.0005 s、引擎动作 0.0009 s、业务规则 0.024 s、状态快照 0.319 s、序列化/落盘 0.171 s。数据以各次证据中的实际值为准。

该样例单次索引/块读取最大约 1.13 ms，状态生成到本地探针可见最大约 21.4 ms。SUMO RSS 采样最大约 43.8 MB，Python RSS 采样最大约 64.9 MB；Python traced heap 峰值约 1.52 MB。RSS 是离散采样，不能冒充连续峰值；延迟不包含 P1 的 HTTP、通知、Canvas 或浏览器绘制。

## 4. 冻结给 P1 的最小语义与初始预算

| 项目 | P1 依据 |
|---|---|
| 状态权威 | SUMO 管道路运动/停靠；Python 管旅客/容量/服务；Host 管产品授权、作业和提交 |
| 业务/执行边界 | 模型输入不接受程序、输出根、环境或预算覆盖；Host 解析授权资源后生成清单；计算端再次校验 |
| 时间 | 固定样例使用 Asia/Shanghai、服务日期/本地起点和单调秒，步长/决策 1 s；历史 DST 与其他时区不在本次验证范围 |
| 相位 | 运动/服务完成及释放 → 到达/换乘完成 → 稳定 ID 的班次/动作预留 → 引擎提交 → 同刻快照；效果在后续观测确认 |
| 时间块 | 10 s 分块，半开 tick 分区，最终块包含时域终点；索引 fromTime/toTime 是实际覆盖闭区间；边界快照是恢复数据，不重算分析事件 |
| 发布 | 文件完成/哈希后发布原子索引；完整块不可原地改；frame sequence 不增加 Canvas/Geo revision |
| 提交/错误 | 已发布块不是成功提交；必须复核最终时刻、输入/代码/产物哈希、原始计数和索引；invalid/failed/cancelled/unknown 分开，无自动补跑 |
| 首批产品规模 | 先限制到已测 600 s、120 辆背景车、100 人；扩大规模前补实跑。探针的 3600 s 仅用于取消/异常检查，不是产品规模承诺 |
| 存储/读取 | 64 MiB 输出预算、每块/事件单次 2 MiB、索引 512 KiB，读取有界；必要事件不能靠降采样消除 |
| 计算/准备 | 计算墙钟 60 s；原生准备探针 120 s，保留冷启动超时与 unknown 处理 |
| P1 验证起点 | 本机块读取先以 50 ms、状态到本地读取 1 s 为检查预算；Host→Canvas 可见延迟、帧率及通知频率需 P1 实测，不沿用本地探针值宣称 UI 达标 |

草案是版本化内部协议，不是永久公共 API，也不是已注册工具 TypeBox 契约。P1 按产品授权/模块装配语义收敛；通用层不因本例而强制所有场景具有疏散节点。
