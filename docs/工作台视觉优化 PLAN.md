# 工作台视觉优化 PLAN

日期：2026-10-24。状态：规划，尚未实施。适用基线：平台 3.24.0 当前工作区。

## 1. 目标与范围

在现有工作台结构上统一视觉系统，让导航、会话、分析画布与辅助界面呈现简洁、朴素的专业工具质感。保留 Light、Dark、Sand 三套正式主题，共用布局、组件尺寸、交互逻辑和信息层级。

本轮围绕整体视觉方向与结构规则开展，不更换 UI 框架，不重做信息架构，不新增任务创建机制或工具执行流程。现有会话、文件、引用、地图、CAD 与报告功能继续沿用已有契约和状态来源。

此前讨论的黑白双主题与退出 Sand 建议不再采用。三张视觉卡片分别代表浅色、深色、Sand 三种主题，不代表三套独立布局。

## 2. 当前基础与证据边界

| 审视项 | 当前基础 | 本轮处理方向 |
| --- | --- | --- |
| 主题系统 | Light、Dark、Sand 已共用 primitive 与 semantic token | 保留架构，统一三主题的层级与状态规则 |
| 默认主题 | `App.tsx` 的 `initialTheme()` 在无有效保存值时返回 `sand` | 保留当前默认行为和已有偏好，不引入迁移 |

| 字号 | 已有 11px 功能文字下限，部分样式仍包含 9–10px 标签 | 核查实际承载功能信息的标签并满足下限 |

## 3. 三主题共同规则

### 3.1 材料语言

| 主题 | 主要表现 | 强调方式 |
| --- | --- | --- |
| Light 浅色 | 白色内容区、浅灰辅助区 | 深色主操作，灰阶选中与悬停 |
| Dark 深色 | 深灰工作区，表面之间小幅明度差 | 浅色主操作，清楚的边界与文字层级 |
| Sand 沙色 | 暖白内容区、沙灰辅助区 | 深暖灰主操作，陶土色限于少量有用途的交互 |

三主题保持相同 DOM、布局、字号、间距、圆角、控件尺寸、操作位置和交互。品牌标识保留，不通过重复品牌色建立所有层级。Sand 与其他主题平级，不因保留品牌主题而增加独立装饰或布局。

以下为候选色板，实施时应在真实表面组合上校准对比度，不视为已冻结的 token 值：

| 语义用途 | Light | Dark | Sand |
| --- | --- | --- | --- |
| 主工作区 | `#FFFFFF` | `#1D1D1F` | `#FAF8F4` |
| 侧栏与辅助区 | `#F5F5F5` | `#232325` | `#F0ECE5` |
| 内容表面 | `#FAFAFA` | `#29292C` | `#F5F1EA` |
| 主要文字 | `#202020` | `#EDEDED` | `#292622` |
| 次要文字 | `#666666` | `#AAAAAA` | `#6D655D` |
| 分隔边框 | `#DDDDDD` | `#414145` | `#DCD5CC` |
| 主操作底色 | `#202020` | `#EFEFEF` | `#39332C` |
| 主操作文字 | `#FFFFFF` | `#202020` | `#FAF8F4` |

### 3.2 颜色与状态

- 常规导航、分组标题、普通图标与标签优先使用文字灰阶，不反复使用陶土色。
- 选中态通过底色配合文字字重、边界或位置标识表达，不能仅靠颜色变化。
- 悬停、选中、键盘焦点、禁用、加载、成功、警告和错误分别核查，避免共用一个强调色造成语义混淆。
- 文本链接采用可识别的文字与交互提示；焦点环在三主题表面上保持可见。
- 地图图层、图表系列、交通状态、警告与错误保留语义颜色，并配合文字、形状或线型表达。
- 三主题只调整工作台外壳；CAD 纸面、导入文档与专业内容不做全局反相。

## 4. 整体结构与容器职责

保留顶栏、侧栏、会话、分析画布和文件区，先统一每一层的视觉职责：

| 层级 | 承载内容 | 视觉规则 |
| --- | --- | --- |
| 应用外壳 | 顶栏、侧栏、辅助工具区 | 连续实色底、稳定对齐、少量分隔线 |
| 主工作区 | 会话、地图、报告、文件预览 | 内容优先，减少重复容器 |
| 对象容器 | 能力模块、附件、结果文件 | 轻边框卡片，统一信息顺序 |
| 临时浮层 | 菜单、弹窗、提示 | 清楚的边界，必要的阴影 |

卡片用于独立对象，列表用于连续记录。能力目录可以使用卡片；执行过程继续使用紧凑行与可展开细节；设置项使用分组列表。不给每段消息、每个工具和每块设置重复套卡片。

侧栏继续遵守固定工具栏下方能力区 30%／会话区 70% 的规则，保留收起机制和移动端默认行为。能力信息继续消费 `platform.getOverview()` 投影，不从外观或概念预览推测可用状态。

## 5. 组件尺度与动态反馈

以下为试排起点，最终数值通过三主题和窄面板画面确定：

| 项目 | 候选规则 |
| --- | --- |
| 功能文字 | 以 12–13px 为主，辅助文字至少 11px |
| 正文 | 14–15px，保留长文阅读所需行距 |
| 标题 | 使用系统无衬线字体，首页与功能标题按层级收敛 |
| 圆角 | 小控件、中型容器、大型弹窗约 6／8／12px |
| 控件高度 | 常用工具栏约 30–34px，表单控件按用途适度放宽 |
| 常驻面板 | 实色背景与分隔线，减少浮起感 |
| 阴影 | 主要用于菜单、弹窗等浮层 |
| 普通按钮 | 取消悬停上移，保留背景、边框和文字反馈 |

### 5.1 动效目标与适用范围

过渡动效属于工作台的共同视觉规则，不局限于 Canvas。适当增加能解释界面变化的过渡：面板从哪里打开、内容如何展开、当前选中位置如何变化，以及附件或结果何时加入。三主题采用相同节奏，不通过额外动画区分主题。

当前源码已经包含侧栏和文件区滑动、菜单与弹窗入场、开关和箭头过渡，以及 Canvas 分栏变化；后续先复用并统一这些表现，再补足缺失场景。CSS 中存在动效声明不等于入场、退出、中断和减少动态效果均已通过运行验收。

| 场景 | 建议过渡 | 行为边界 |
| --- | --- | --- |
| 按钮、导航行、卡片与开关 | 背景、边框、图标或开关位置连续变化 | 保留直接反馈，不让普通按钮悬停浮起；键盘焦点立即可见 |
| 侧栏、文件区与 Canvas 面板 | 沿所在边缘展开或收回，关联区域同步调整 | 保持空间方向；拖动分栏时直接跟手，不叠加缓动 |
| 标签页、会话与设置分区切换 | 选中标识过渡，必要时对新内容做短淡入 | 切换立即生效，保留各区滚动、焦点和草稿；不将整页反复滑动或缩放 |
| 工具详情、思考区与侧栏分组 | 展开尺寸变化配合轻淡入，箭头同步转向 | 保留展开选择、阅读位置和时间线关系；不每次流式增量都重新播放 |
| 菜单、弹窗、提示与引用详情 | 围绕触发位置或层级关系短淡入、轻位移，并补足适用的退出过渡 | 关闭立即更新交互状态，退出元素不截获点击或键盘焦点 |
| 输入区附件、上下文和待处理队列 | 用户添加或移除项目时，局部显隐与相邻项目让位 | 不延迟发送、删除或队列消费；初次载入历史数据不逐项重播 |
| 结果文件与加载完成 | 新结果一次性出现，加载占位向内容做短过渡 | 不对整段回复逐字或逐块编排入场，不伪造进度与成功状态 |

### 5.2 节奏与实现规则

以下为动效试排起点，按位移距离、区域大小和实际响应校准，不统一缩短已有时长：

| 用途 | 候选时长 | 节奏 |
| --- | --- | --- |
| 悬停、选中与控件反馈 | 100–160ms | 反馈立即开始，不附加等待 |
| 菜单、提示与小型浮层 | 140–200ms | 短淡入，必要时配合小位移 |
| 内容展开、标签内容与附件增减 | 160–240ms | 保持上下文与相邻内容的连续性 |
| 侧栏、文件区及较大面板 | 240–320ms | 按结构方向减速到位 |
| 地图或 Canvas 大范围视野切换 | 按用途保留约 400ms 的起点 | 与普通控件分开校准，避免影响地图操作 |

- 优先复用现有 CSS 过渡和组件生命周期，时长与缓动统一声明于 `tokens.css`；不为增加动效引入动画库或全局调度框架。
- 明确需要过渡的属性，避免 `transition: all`。淡入和位移优先使用 opacity、transform；只有真实展开或分栏才处理布局尺寸。
- 快速开关、反向操作与连续切换应从当前状态继续或直接完成，不能排队播放、闪回旧内容或等待动画结束后才处理操作。
- 新增循环动效只用于真实的执行或加载状态，结束后停止；不增加卡片漂浮、装饰闪烁和大规模列表错峰入场。
- 不依赖动画结束事件保证发送、保存、取消、关闭或焦点恢复；减少动态效果时，界面仍直接到达正确状态。
- `prefers-reduced-motion` 下移除空间位移、缩放及非必要循环；保留文字、图标或即时颜色反馈表达状态。

## 6. 工作区域改造范围

| 区域 | 工作内容 | 区域验收重点 |
| --- | --- | --- |
| 顶栏、侧栏、标签页 | 统一背景层级、行高、图标、选中与悬停；减少普通导航的强调色 | 长任务名、多个标签、折叠与窄窗口仍能识别当前上下文 |
| 会话与输入区 | 通过位置、间距和轻底色区分用户输入、Agent 输出、执行记录与结果文件，减少容器嵌套 | 长会话、工具展开、流式输出和队列状态可辨；保留滚动、输入和交付语义 |
| 首页与空状态 | 收小衬线大标题，弱化放大水印，突出已有新建任务入口与必要引导 | 下一步操作清楚，首轮不新增任务创建机制或首页专用数据流 |
| 设置与模型 | 统一分组、搜索、配置列表和操作样式，减少装饰性嵌套 | 配置、禁用、不可用和异常反馈在三主题下清楚 |
| 能力中心 | 卡片统一为名称、说明、状态与操作的顺序 | 长名称、长描述、安装与异常状态不破坏布局；状态来源保持不变 |
| 地图、CAD、图表与报告 | 外壳使用统一主题，保留专业内容的颜色与纸面语义 | 图层、选区、批注、图例、报告正文可辨；从配色阶段开始验收 |

## 8. 实现边界

- `src/web/styles/tokens.css` 继续作为 primitive 与 semantic token 的唯一声明源。优先使用已有语义，确有不同职责时再补充，不引入第二套主题系统。
- 组件消费 semantic token；禁止主题专属色值和 `[data-theme] .component` 覆盖。结构尺度如需调整，保持现有刻度与别名一致。
- 样式落在 `src/web/styles.css` 或遵守其现有分层；不引入新组件库，不清理无关代码，不手改生成物。
- 改动组件结构时保留键盘、焦点、滚动、输入法、附件、队列、引用和成果入口的既有行为。不得借视觉调整扩建通用重试、状态或任务系统。
- 多区域联动的实现走分支、PR 与合并流程。当前落档只增加文档，不创建实施分支或变更 UI。
- 发布记录归入当前未发布版本，不因本计划提升平台版本；若后续实际修改 Module 内容，再遵守模块独立版本纪律。

## 9. 验收矩阵与检查方式

以下场景均覆盖 Light、Dark、Sand：

| 场景 | 检查重点 |
| --- | --- |
| 首页、空会话、空文件区、空能力目录 | 主操作清楚，空状态不产生额外容器噪声 |
| 长会话、长任务名、长文件名、多标签 | 文本截断可理解，内容不溢出，完整名称可访问 |
| 执行中、已完成、失败及现有排队状态 | 状态变化可见，工具细节可展开，保留原有输入与交付行为 |
| 紧凑窗口、窄会话栏、多面板、侧栏折叠 | 不依靠缩小字号容纳内容；必要滚动留在对应区域 |
| 地图、CAD、图表、报告与文件预览 | 数据、选区、图例、纸面和应用外壳互不混淆 |
| 菜单、弹窗、提示、表单 | 焦点、层级、错误与关闭入口清楚 |
| 面板开合、分区切换、详情展开、附件与队列增减 | 录屏核对进入和退出；连续及反向操作无闪回、残留遮挡或延迟；滚动位置稳定 |
| 长输出、批量结果与分栏拖动 | 不反复播放内容入场；输入响应不等待动画；拖动直接跟手，检查明显卡顿与持续布局抖动 |
| 键盘操作与减少动态效果偏好 | 焦点可见、顺序合理、既有操作可达，减少动态效果生效 |

功能文字对比度以 4.5:1 为目标；必要的控件边界、焦点和状态标识检查 3:1。每个值在实际背景上核验，不能只比较主题色表。装饰分隔线不机械套用功能边界标准。

实施前运行 `npm run typecheck:react` 建立基线；相应改动完成后运行 React 类型检查，涉及交互后运行 `npm run test:web`。执行测试前先运行 `npm run test:budget`，新增检查优先并入已有关键场景，注册测试总数不得超过 40。

文档落档不执行构建或应用功能测试。正式验收记录区分概念预览检查、真实 Web 应用检查与 Electron 实机检查，不用前者替代后两者。

## 10. 完成标准

- 三主题作为同一产品的平级外观选择，布局、尺寸和操作一致。
- 内容、导航、对象卡片和临时浮层各有清楚的视觉职责。
- 首页回归任务入口；暖色强调、展示型大标题、品牌水印和浮起效果得到收敛。
- 所有功能文字满足项目字号下限，关键文字、控件和状态通过对比度检查。
- 交通数据颜色、CAD 纸面、报告阅读和既有功能不因外观调整受损。
- 过渡动效覆盖有需要的导航、展开、浮层与内容变化，三主题节奏一致；连续操作、阅读位置和减少动态效果通过验收。
- P0–P4 的证据与剩余问题记录完整，再确认视觉优化完成。
