## P4 / V3 受管 Run 与班表变体

0.5.0 首个纵向场景采用单线路、单列实体列车、一个服务班次与三个合成站台。场景显式选择实体模式，保留线路、服务、车辆与站台的独立 ID。既有有限班次模型沿原配置回放。变更班表时使用 `railTimetable`，Host 拒绝同时变更轨道、站台、运能、需求等共同条件。

TraCI 实际停站进入既有事件块。SUMO 的原始时刻与推进步确认时刻分别记录。例如基线中途站原始离站为 390 s，账本在 391 s 的推进步确认，位置回放可定位至 390 s 的有效帧。实际离站时从已就绪队列按容量确认上车，终点站实际到站后确认完成。Host 按同一 Run 的 `tripinfo.xml`、`stops.xml` 与事件复核停站和承运，并将列车剔除出道路车辆统计。

## Simulation Canvas 布局与默认指标

**布局优化通过已测范围的验收。** 地图是主视区，时间轴常驻，详情按需展开。以下结果限于本机、已测窗口和合成样例。多硬件、大规模交通对象及更小窗口另行验证。P4 的模型验收按各独立场景判定。

运行概览压缩为横栏，地图承载图层、底图、可折叠图例及视角操作。时间轴与进度独立于详情滚动。对象、事件、班表和配对结果共用一个抽屉，默认高度随窗口收缩，支持折叠、展开、拖动和键盘调节。画布保持同一 MapLibre 实例。默认指标按纯道路、有限多方式和实体地铁 Run 的数据选择，任务级视图配置见 PLAN 5.5。

使用同一上海实体地铁 Run 对照测量。1600×1050 窗口的地图从约 449 px 增至约 698 px，占 Canvas 内容高度约 47% 和 73%，折叠后约 818 px（86%）。1280×720 窗口默认地图占比约 65%。在 980×620 和 800×560 窗口展开抽屉后，地图分别保留约 219 px 和 213 px，时间轴与抽屉均在 Canvas 范围内。

真实 Host 回放复核了拖动、键盘恢复、图层显隐、OpenStreetMap 瓦片、跨标签保留观看时刻，以及 391 s 确认事件对应 390 s 位置帧。折叠时地图实例和选中列车的相对视角保持一致，未触发 Run 数据请求。另复核纯道路及旧班次的指标、普通 Geo 的图例、选区和截图。对照截图及测量见 `tmp/simulation-canvas-layout/`。

P2 三组配对结果仍可在详情抽屉查看，冻结报告可打开。React 类型检查与 Web 冒烟通过，证据为 `comparison.json` 和 `web.log`。
