## 2. T1：预留 JSONL 路径

实际运行：2026-10-25 13:03（Asia/Shanghai）。四个全新 Pi 使用 `--session sessions/transportx/conv_<uuid>.jsonl`，不预写 header 或消息。

发现并修正探针前提：Pi 不创建预留文件的父目录。首次未建 `sessions/transportx/` 时，正常/失败/中断均返回 ENOENT；建立父目录后通过。生产实现必须在预留历史地址时创建父目录，JSONL 本身仍由 Pi 写入。

结论：空会话身份必须由 Manifest 保存；失败或中断有时会留下真实 assistant 记录，不应一概视为空历史。本证据不承诺 Pi 在 assistant 落盘前保留全部用户输入。

## 5. T4：本机门禁原型

`workspace-gate-probe.mjs` 启动两个独立配置的 Host actor 和真实 Pi，使用 canonical cwd、原元数据租约及独立持久 runtime generation。它是脚本内原型，不接入生产 Host。

已验证：

1. 通过不同 agentDir 及路径别名竞争同目录，只允许 A 启动 Pi；B 收到 writer_busy。
2. 等真实 Pi 进程树停止后交接，另一 Host 可启动。
3. Host 被 SIGKILL 后，原受管作业仍存活；旧元数据租约可回收，但未确认运行代次仍返回 process_stop_unconfirmed。
4. 仅使用探针持有的确切 ChildProcess handle 停止其作业；独立核验 Pi 退出、锁代次一致后才可恢复。过期代次被拒绝，没有忽略检查入口。
5. 文件系统门禁原型拒绝 damaged 目标，允许 healthy 和 new；全局 blocked 或全局记录损坏时全部业务写被拒绝。

实现约束：运行租约不能直接复用“Host PID 死亡即可接管”的元数据语义；必须保留运行代次与待核验阶段。启动中 Host 崩溃且 Pi PID 尚未记录时保持阻塞，不推断未启动。未知/PID 重用的进程不可自动停止。生产诊断、恢复 API、作业关联证明和跨平台进程观测仍须在 A/B 场景实现验证。

## 8. PR 1 进行中：统一创建与运行租约实现

`workspace-service.ts` 共用两类创建的计划/记录初始化：先校验模型与模块，再预留目录，提交 plan/Manifest 后才向调用方返回 created；创建服务不启动 Pi。新目录保留原归属证明并记录创建 requestId/摘要；未知既有目录不覆盖、不递归清理。已有工作区在完整读改写租约内先去重，再核验 expectedRevision/defaultsRevision；修改名称或默认值后，重试原请求仍返回原记录。Manifest 已提交、catalog 更新失败时从 creating 记录与已提交 Manifest 继续发布。

既有 session-boundaries 场景增加验证：取消/无创建无任务目录；模型/模块静态校验失败不预留任务；空会话有稳定记录但无 JSONL；同目录两条历史与计划独立；覆盖不更新默认；新默认不回写旧会话；并发相同请求不重复创建；catalog ENOSPC 后找回同一会话且不增加工作区。

`workspace-runtime.ts` 实现独立运行租约与完整生命周期日志，`process-inspection.ts` 读取平台 profile 提供的内核身份。macOS 使用 SDK 中 proc_bsdinfo 的微秒启动时间及 proc_pidpath；Linux 使用 /proc start ticks 与 executable；Windows 使用 CIM CreationDate/ExecutablePath。系统 boot identity 区分重启前后；不把 Node process.title 或秒级 ps 时间当作持久进程身份证明。未知身份不自动停止，PID 复用不会触发终止；运行日志不包含服务 token 或完整命令参数。

独立 `scripts/workspace-runtime-smoke.mjs` 已在 macOS arm64 用实现中的运行门禁与真实 Pi 验证：不同配置 Host/路径别名只能运行一份 Pi；确认 Pi/作业停止后可交接；SIGKILL Host 后残留作业阻止接管；过期代次的 stop-owned 不停止作业；当前代次显式停止已核验进程后恢复。此冒烟不是生产 Host/API 的完整接入验收。

故障边界：spawn 的 PID 已记录但身份未提交时，只有确认 PID 已不存在或系统已重启，才认定其停止；PID 尚在且身份未知时不能自动终止。若崩溃发生在 spawn 与 PID 记录之间，保持未知门禁；无法另行识别时通过系统重启后的 boot 核验恢复，没有强制忽略检查入口。生产诊断 UI 仍需呈现这些原因和操作步骤。

ProcessRunner 已在活动工作区租约内登记受管 native 进程的启动意图、内核身份和停止提交；无会话的健康探测沿原执行路径。该跟踪随 native 子进程完成而提交，不在其结果返回后另行补写。新冻结计划中的工作区、模块入口、native runtime 和资产路径均序列化为 POSIX。

后续仍须接入 Pi 生命周期、状态同步、迁移协调和唯一 API，再完成私有状态/全部客户端切换。未运行用户数据迁移，未提升平台版本，未通过 A/B 完整验收。
