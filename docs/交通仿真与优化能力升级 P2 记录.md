# 交通仿真 P2 实施记录

状态：**在合成场景与 macOS arm64 已测范围内通过 P2 退出条件。** 日期：2026-11-11。前置 P1 提交 `2dadde3`、草稿 PR [#107](https://github.com/Ran2424/transportx-agent/pull/107)；分支 `codex/traffic-simulation-p2`。可核验摘要见 [P2 证据](acceptance/traffic-simulation-p2.json)。

## 范围与架构

按用户确认仅测试小型合成场景，不做真实虹桥校准。修改前 P1 只有单疏运点固定服务与单 Run 回放，没有多点有限车队、配对清单及比较报告。仍以 ARCHITECTURE 为权威：Module 贡献 Skill/Extension/Python/Data，Pi 调用现有 Host；Host 逐个 Run 复用 Job、进程和所属会话边界；Simulation Canvas 复用既有 Adapter/Kernel、Geo 地图原语及 Document 打开入口。没有新增 Runtime、Planner、实验调度器、策略注册中心或优化求解器。

P3 真实数据校准按用户要求暂缓；P4 目标平台成品分发、P5 自动优化不在本阶段通过范围内。

## 代码改动

- Traffic Simulation **0.3.0**、Data **0.2.0**，新增严格的 multimodal 输入及第五个批准工具 traffic_experiment；保留 road/evacuation。Module 版本及契约同步，平台沿用 3.24.2 未发布段。
- 同一 TraCI 入口新增有限服务账本：节点候车容量、泊位预留、固定选择旅客、有限公交/网约车、多趟往返及有限地铁接续。命令接受与实际离站分开；目标满载时旅客留在车上，实际返场停稳后车辆才再次可用。每 tick 核对人数、载客、节点/泊位守恒。
- 固定基线与公交队列阈值规则并存。反馈仅读取当时已到达队列，记录观测、候选、拒绝、预留、引擎接受及实际执行。保留动态 feedback- ID 命名空间，不读未来需求。
- Host 冻结父场景和显式干预，拒绝未声明差异、改变共同条件或空干预；可绑定当前所属会话的真实 Geo viewport/rectangle，冻结上下文及哈希，要求全部服务点在范围内。
- 实验限两个场景、1–3 个不同种子、6 Run / 3600 仿真秒 / 6×64 MiB 输出预算，派发前冻结。槽位顺序受理且只绑定一个 Run，同调用去重，新调用不能覆盖旧槽位。失败/取消/unknown 保留，不自动补跑。
- JSON/Markdown 比较按内容哈希冻结，包含共同条件、干预、来源、网络、Geo context、Run/Job/result/code 哈希和原生运行时身份。只读 GET 不生成报告；显式工具查询生成快照。存在未完整配对时禁止正常收益结论。
- 指标区分枢纽/全程等待、均值/P90、完成者与全到达者截尾耗时、线路/节点积压、末班未接续、实际趟次、车队占用/载客率/完成周转与未返场截尾。Host 按必要事件重放及原始 tripinfo 独立核对，不只信退出码或 Python 摘要。
- Canvas 增加同刻车队/节点/线路详情与配对表，区分终点比较和观看时刻；报告复用 Document。更换对象后重置“已附加”状态；索引响应用同一完整索引投影计算/发布时刻，避免轮询摘要滞后。

## 真实模型与有限资源验证

合成网络为 UTM51N 小回环，4 条单向双车道边，WGS84 为示意定位。两个上客点、两个目的地接续点、4 条固定线路（两公交、两网约车），2 辆容量 2 公交和 2 辆容量 1 网约车。上客点容量 4、接续点容量 2，泊位固定。16 人，每个上客点 6 公交 + 2 网约车，背景车 12，600 秒，跨午夜且末班容量明确。

基线固定班表，变体只改 policy：公交队列阈值 2、冷却 30 秒。不改旅客/车队/道路/线路/班表。实际两方案均为 10 趟，不能声称实际增开趟次。独立核对逐人唯一登乘、容量、满载保留、上游受阻、步行接续截止点及实际返场，保留全部未完成状态。

最终包 Installer→Assembler→Host→Python→SUMO 六槽位及真实 SIGKILL 证据：`tmp/simulation-p2-experiment-030/evidence.json`。该技术证明与真实模型自主任务分开，不用固定响应代替产品验收。

## 性能、限制与下一阶段依赖

产品上限保持 P1 的 600 秒、120 背景车、100 旅客；多方式另限 4 节点/4 线路/4 车。合同内部较宽上限不代表产品已测支持。实验至多 2×3 Run 顺序执行，不支持任意规模批处理、运行中改参或线上控制。

实际 120 背景车/100 旅客代表样例通过守恒及 Host 指标复核，墙钟 5.58 秒，保留 94 个未完成者，见 tmp/simulation-p2-statistics-final/evidence.json；六个 Python 文件与独立包哈希一致。拥塞样例“可以计算”不代表已充分疏运。小场景约 1.6–1.7 秒；原生 Host 首槽位约 16.6 秒，随后约 3.7–3.9 秒，均在 60 秒预算内。播放/可见延迟/内存和输出预算沿用 P1 已测门槛，不把 RAF 调度频率当作车辆帧率。
