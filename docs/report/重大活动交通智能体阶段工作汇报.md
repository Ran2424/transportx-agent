## 一、一句话定位

本项目建成了一套 **"可信数据 + 受控智能体 + 交互式决策界面"** 的重大活动交通分析系统：

> 把分散、异构、口径不一的徐汇区多业态交通原始数据，治理成一套面向智能体的受控数据资产；让 AI 智能体在严格的口径、安全和权限约束下完成多方式交通分析、结构化任务编排和交互式地图呈现，辅助重大活动交通态势洞察与决策。

原始数据位于外部受控目录（`揭榜挂帅/data/徐汇区各业态数据`，共 10 个 CSV/XLSX 文件、约 165 MB），**不进入本项目**。本项目内的全部数据产物均为对原始数据的二次加工或新增成果（治理后的分域数据库、数据字典、查询接口），原始文件可随时从受控目录重新构建。

## 三、Agent 线：智能体工作台

**目标：让 AI 智能体像一个"可管控的交通分析师"一样工作，而不是一个自由发挥的聊天机器人。**

### 3.1 多会话 Agent 工作台

- 自研 Node 服务管理多个 AI 智能体子进程（Pi RPC 模式），浏览器中可并行创建、切换、恢复、关闭多个分析任务；每个任务有独立工作目录，形成天然的权限边界。
- 会话历史以 JSONL 为准，支持断点恢复、历史回放、按最近对话排序；刷新页面或重启服务后可恢复到上次分析现场。
- 流式展示回答、思考过程与工具执行，每一步"Agent 在查什么表、跑什么脚本"全程可见、可审计。

### 3.2 任务模式：把"分析过程"变成可观察的结构化状态

- 自研任务模式扩展（`pi-task-mode`），提供 `tau_task` / `tau_ask_user` 两个工具：复杂分析前智能体必须先拆解 2–8 个步骤，执行中持续更新"进行中/完成/阻塞/失败"，界面上实时呈现任务看板。
- **人机交互闭环**：信息不足时智能体调用结构化询问（确认/单选/短文本/长文本），暂停等待用户回答后继续；**用户取消绝不视为批准**，取消后任务转入明确终态。
- 任务状态全部走版本化结构化协议（TaskSnapshot），界面不解析智能体的自然语言，杜绝"看起来像完成了"的误判。

### 3.3 声明式地图：智能体只能"描述"地图，不能"执行"地图

- 自研地理可视化扩展（`pi-geo-visualization`），提供 `publish_geodata`（发布数据资源）与 `present_visualization`（地图命令）两个工具。
- **白名单式协议（GeoScene）**：智能体只能通过 14 条受控命令渐进构建地图（建图、加图层、设色、弹窗、视角、选择、清除），无法生成或执行任何 JavaScript/HTML/CSS；每条命令只改一个关注点，每次成功返回递增版本号的完整快照。
- 地图数据按会话隔离发布，带 SHA-256 校验、大小与要素数上限（20 MB / 5 万要素）、路径越界防御；浏览器端 MapLibre 按需加载，支持增量更新、图层显隐保持、安全弹窗。
- 这一设计是本项目的关键安全资产：**AI 输出永远只是数据，永远不会变成可执行代码**。

### 3.4 工程可信度

- 共享契约（会话/任务/地图/桥接）由智能体、服务端、浏览器三方共用并各自独立校验，带版本诊断。
- 默认 56 项自动化测试全部通过，另有真实浏览器端到端冒烟（双会话、任务模式、地图、五类人机会话、移动端）与真实智能体协议冒烟；覆盖路径穿越、跨会话资源隔离、Markdown 安全渲染等安全边界。

## 四、知识线：把专家经验固化成智能体的"工作手册"

**目标：智能体每次分析都遵循同一套口径、规范和红
线，而不是每次重新猜测。**

### 4.1 交通数据资产知识库（shanghai-traffic-data-assets）

143 行总纲 + 11 份分域参考文档（覆盖、表结构、空间契约、指标口径、治理、6 个分库数据字典），固化了：

- **查询纪律**：先发现（coverage/business/order-sources）再查询，禁止凭表名猜粒度；SQL 必须使用全限定对象名。
- **口径红线**：订单数、端点事件数、场馆事件数严格区分，禁止把两个端点加成两单；公交交易数、轨交人次、网约车事件量纲不同，禁止相加为"综合客流"；演前/演中/散场默认分析窗口（15–19、19–22、22–24）不得冒充演出起止时间；原始订单号未分发、禁止尝试恢复。
- **输出要求**：每次回答必须说明使用的事实表、时间范围与粒度、覆盖范围、单位、坐标系及推定记录处理。

### 4.2 制图规范知识库（geo-visualization-explanation）

- 渐进建图工作流：先查数据、再发布、后建图；一条命令一个关注点；校验失败两次即停止重试、保留最后成功地图。
- **上海地铁官方配色表**：1—18 号线及浦江线的官方线路色值（源自申通地铁官方线网图并转换为 Web sRGB），智能体绘制地铁线路时必须按表设色，不得用通用色板。
- 数据上限、WGS84 坐标契约、弹窗/图例/POI 标注等可读性规则。

### 4.3 图表模板库与会话行为规范

- `plot-from-data`：9 类可复用图表模板（分组柱状、配对差值、热力、置信带、雷达双序列、断轴散点等）+ 8 个参考脚本，保证统计图表风格统一。
- 会话系统提示（`PI_SESSION_CONTEXT.md`）：固定 Python 解释器、路径引用规则、单命令单查询原则、查询脚本调用规范，从源头减少智能体执行错误。

## 五、数据线：从原始表格到受控数据资产（本期最重的工程）

**目标：把 10 个异构原始文件，治理成智能体可安全、准确查询的一套多方式交通数据资产。**

### 5.1 原始数据盘点（外部受控目录，不入库分发）

| 原始文件 | 内容 | 规模 |
|---|---|---:|
| 网约车出发表.csv | 上车记录 | 64.1 万行 |
| 网约车到达表.csv | 下车记录 | 63.5 万行 |
| 支付订单上车地点是上海体育场.csv | 场馆离场订单 | 57.9 万行 |
| 支付订单下车地点是上海体育场.csv | 场馆到场订单 | 57.2 万行 |
| 公交线路客流.csv | 半小时线路客流 | 5.5 万行 |
| 公交线路站点基础数据.xlsx | 线路/站点/站序 | 77 线、194 站、652 站序 |
| 轨交数据.csv | 站点小时进出站客流 | 7,975 行 |
| 路网发布段状态(逢变更新).xlsx | 路段状态变化事件 | 2.2 万行、89 个发布段 |
| 气象数据.csv | 网格分钟级气象 | 1.1 万行、8 个网格 |

原始数据典型问题：**多坐标系混杂（GCJ-02 / BD-09 / EPSG:32651 / 未标注）、订单号明文、重复订单、千分位数值、时间格式不一、覆盖期不完全一致**。

### 5.2 资产化成果（本项目新增/加工产物）

构建为 6 个分域 SQLite 库（约 527 MB），按"目录—公共—道路—轨交—公交—订单"分域组织：

- **统一订单模型（核心成果）**：120.6 万条唯一订单一单一行；226.9 万个上下车端点；115.1 万条场馆到/离场事件；15 分钟、小时、日三级业务聚合集市，智能体无需扫描百万行明细即可回答趋势问题。
- **全链路治理**：32 个源数据集全部登记血缘；构建记录源库哈希、坐标标准、时区和构建时间；构建内置断言（订单唯一性、集市加和恒等式、错误级质量规则全部通过）。
- **只读查询接口**：`query_assets.py` 强制只读（`PRAGMA query_only`）、SQL 前缀白名单、对象名校验、行数上限，并提供 `--coverage / --business / --order-sources / --metrics` 等"先发现后查询"命令。

### 5.3 三项特别手段（可向领导重点汇报的技术亮点）

**亮点一：发现并纠正了"两套订单重复计数"的隐患。**
通过订单号回连分析发现：场馆到场/离场订单与网约车上车/下车订单属于**同一订单体系**，场馆订单 97.48% 与网约车订单重叠（105.5 万中重叠 102.8 万）。若按两套事实建库，客流会被系统性重复计算。为此重构为统一订单事实：四源合并、一单一行；同时命中两个场馆源且字段冲突的 9 条订单**不静默覆盖**，采用离场源优先并打冲突标记，全程可审计。

**亮点二：场馆坐标系的"证据链反推"，避免大面积二次偏移。**
场馆订单没有坐标系字段，简单粗暴地按 GCJ-02 统一转换是行业常见错误。本项目按订单号回连上/下车表继承显式坐标系；回连为未知的保留 UNKNOWN；无法回连的才按数据集多数假设兜底，且每条记录都有字段级证据标注。实测发现离场订单中约 7%（4 万余条）实际为 WGS84，若统一转换将被二次偏移——这一错误被提前拦截。

**亮点三：隐私与口径的内生化设计。**
原始订单号不进入资产库，四源合并仅使用 SHA-256 哈希假名化；无法确认坐标系的记录不删除但禁止参与精确空间分析；各类"不可违反的口径"（量纲不可相加、事件数≠订单数、分析窗口≠演出时间）写入知识库强制约束智能体输出。

### 5.4 当前数据边界（如实说明）

- 各事实域约 21—22 天数据，适合活动期对比，不支持季节性/年度趋势；
- 轨交客流覆盖 10 个物理站、道路仅 89 个发布段且无几何、天气网格坐标系未确认——分析结论不外推全市；
- 待补：道路几何/权威路网映射、天气网格坐标确认、官方开门与管控时间、空间网格化隐私集市（250/500 m 阈值待定）。

## 八、总结

本期工作的核心价值不在于"接了一个大模型"，而在于三层可信体系的建成：

1. **数据可信**——原始数据经过统一订单建模、坐标证据链治理、隐私脱敏和质量断言，智能体查到的每一个数都有口径和血缘；
2. **行为可信**——智能体的规划、询问、制图全部走结构化契约，过程可视、状态可恢复、取消不视为批准；
3. **输出可信**——地图和图表由白名单协议渲染，AI 输出永不变成可执行代码，口径红线写进知识库强制执行。

这套"可信数据 + 受控智能体"的架构不绑定具体活动案例，可直接复用到后续其他重大活动交通保障场景：替换数据资产和案例知识，工作台与分析链路原样保留。
