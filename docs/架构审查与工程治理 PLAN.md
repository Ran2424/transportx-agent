## 1. 决策与范围

保留模块化单体。Electron 管理桌面生命周期和原生权限，桌面、Web 与 CLI 共用 Agent Host。Host 管理工作区、会话、模块装配、资源和受管作业。Pi 按冻结计划驱动模型和工具运行。React 经 Browser Kernel 发命令、接收事件，在重连后通过 Host Snapshot 恢复投影。

当前产品按**单用户工作站**部署。接入同一 Host 的设备共享工作站信任域。登录授予实例访问权，工作区 ID、资源哈希和工具 token 分别约束资源与工具调用。Pi 基础工具和可信扩展拥有本机进程权限。互不信任的用户共用 Host 超出当前部署边界。若未来有明确的多用户服务需求，单独设计用户与工作区归属、对象级授权、事件范围、文件系统、模型凭据和执行身份隔离。 [现行安全边界](ARCHITECTURE.md#7-安全边界)

本轮后续工作优先修复已有证据支持的缺陷。拆分依据是职责和状态归属。采用现有契约、运行门禁与测试入口，跨边界确有替换或测试需要时再增加接口。

## 3. 目标架构与事实来源

| 层 | 职责 |
|---|---|
| React、CLI、Electron | 发起用户操作，展示加载、空状态、错误和恢复入口。Electron 持有原生窗口和桌面权限。 |
| 协议适配 | Browser Kernel 将用户操作编码成请求，并把事件、Snapshot 转为客户端状态。Host 的 HTTP、WebSocket 和内部工具入口校验不可信输入，转换请求与输出。 |
| Host 应用操作 | 根据认证主体或服务身份做授权，协调会话、命令、作业及恢复。查询和可能提交持久状态的操作各有明确入口。组合根负责装配。 |
| 领域服务 | Workspace／Conversation 负责身份与运行绑定，Module 负责版本和能力，Geo、CAD、Simulation、Citation 等负责各自的业务规则与成果。 |
| 基础设施 | Pi RPC、文件系统、JSONL、Python、SUMO 和原生进程执行 I/O，管理超时、取消和退出。 |

调用由客户端经协议适配进入 Host 应用操作，再进入领域服务和基础设施。源码依赖向契约与应用操作收敛，具体基础设施由组合根装配。持久化清单归属工作区和会话身份，Pi JSONL 归属已完成历史，冻结计划归属模块版本与资产绑定，各领域服务归属自身成果。Snapshot、事件和 Canvas 只向各自客户端投影。 [现行事实来源](ARCHITECTURE.md#4-契约与事实来源)

兼容性检查以已发布 HTTP、WebSocket、CLI、外部 Module manifest 及工作区清单、Pi JSONL、冻结计划、旧 Geo／Video 成果为基线。发现安全修复需要改变拒绝行为时，在对应 PR 明确影响范围。内部替换在同一 PR 切换调用方并删除旧入口。历史读取路径的删除须先有版本范围、fixture 和数据迁移或可读性证据。

## 4. 分阶段实施与验收

### 第一阶段 · 访问边界与供应链

**PR 1 · WebSocket 认证生命周期（P0）**

- 先在现有 WebSocket 和认证场景补充回归。让 HTTP 与 WebSocket 共用有效期及失效判定，明确 Cookie、Basic 和项目认证各自能提供的到期或撤销信号。校验握手、初始状态与后续投递，凭据到期、变更或授权撤销时从投递路径移除并关闭失效连接。心跳承担连接健康检查。已有连接的续期或重连沿用已验证的客户端行为。
- 验收要求：仅携带过期 Cookie 的 HTTP 请求返回 `401`。从到期或已观察到的撤销时刻起，Host 停止排入新事件，关闭原连接并释放定时器和订阅。验证无需等到下一次心跳，覆盖握手后、初始事件投递前失效的窗口。覆盖凭据变更、主动撤销、重新登录恢复和正常断线。保留 Basic、项目认证、桌面、Web 和 CLI 的合法流程。复核已有认证来源可提供的撤销时效，将不能即时观察的情况写入 ADR。
- 只涉及认证、事件连接及相关回归。在独立 PR 中回滚代码即可恢复原行为，无存储迁移。回滚会恢复已知投递缺口，须在变更记录中说明。

**PR 2 · 生产依赖治理（P1，与 PR 1 并行）**

- 干净安装，基于锁文件和实际打包产物确认依赖路径、版本和可达入口。优先处理使用不可信文件的 SheetJS 路径。先验证现有 OOXML 查看器与 XLS／ODS 的能力差异，再对旧格式解析作替换或隔离决策。核对 Mermaid 调用和打包解析器版本，核对更新器实际的嵌套依赖及更新源凭据。
- 验收要求：每个严重或高危条目有证据和处置结果。可达问题有修复或隔离验证，延期项记录责任域、理由和复核条件。回归表格预览、报告 Mermaid 和桌面更新，核对锁文件和制品。Pi 变更另验原生 RPC、资源发现补丁和兼容版本。

### 第二阶段 · 运行生命周期与数据一致性

**PR 3 · RPC 账本与运行代次（P1）**

- 分开管理运行代次、活跃额度和去重证据。一个运行实例的未知命令继续阻止同标识重执行。确认该实例终止且无法再产生结果后，释放活跃额度，按已定义的重放范围保留必要去重或拒绝证据。定义迟到回执、过期标识与 Host 重启的行为。
- 验收要求：丢回执但已执行、同 ID 重试与冲突、迟到回执、退出未确认、确认退出后新实例分配额度、跨代重放均有断言。未知结果保有既有业务含义，关闭旧实例后无需重启 Host 便可恢复可用容量。

**PR 4 · 仿真只读查询与受控恢复（P1）**

- GET 列表、索引、实验及回放读取已发布成果。将恢复放到已有写入权限与工作区运行门禁覆盖的明确操作或受控后台流程。验证进程归属、退出和成果完整性后再提交状态及释放占用。为未发布、损坏和未确认退出保留独立诊断。
- 验收要求：重复与并发 GET 保持运行记录、对比成果和占用标记原字节不变。进程终止或 Host 重启后恢复可重复执行，完成、取消、未知及占用状态可核验。用真实 SUMO 和历史 Run fixture 验证回放、对比和冻结证据。

**PR 5 · HTTP 失败处理、文件流与配置提交（P1）**

- 统一 handler rejection 与响应收口，处理已发送响应头、提前关闭和流故障。认证配置提交成功后更新内存并广播，失败保留上一状态。为工作区、日志及模块目录的本机操作复用明确的准入规则。单独核对完整 Origin、反代头信任和匿名健康响应，保持本地探针可用。
- 验收要求：同步抛错、异步拒绝、磁盘写失败、Range 中途失败和客户端断连均能定位，操作计数和句柄释放，重复响应和未处理 rejection 为零。验证远程、本机、可信反代与 CLI 的预期行为，客户端错误及诊断不暴露凭据。

## 6. 交付规则与审查基线
