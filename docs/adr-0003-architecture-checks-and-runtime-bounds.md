# ADR 0003 · 架构检查与运行上限

2026-11-14 · 已采纳

## 依赖检查

使用仓库已有 TypeScript 解析器检查可解析的相对导入。运行时、类型、静态动态导入和字面量 `require` 都参与依赖图。契约层独立，浏览器内核可依赖契约，React 可依赖契约和内核，Host 与桌面可依赖各自的实现及契约。检查纳入仓库代码，包含新增文件和 CSS／Python 行数。计算生成的导入路径、包依赖和 CSS 导入顺序由各自构建和业务回归覆盖。

存量清零后移除例外基线。[CI 架构检查](../scripts/check-architecture.mjs) 发现文件超过 500 行、反向依赖或循环边即失败，`--report` 输出完整清单。CAD 几何类型归契约定义，解析器向类型单向依赖。SUMO 原生运行时的校验与迁移归桌面打包工具，共用探针调用该实现。包含大型夹具的测试沿用 40 个直接注册节点的预算，按职责拆分的断言由原测试入口显式调用。

生产依赖审计在浏览器任务前生成可下载报告。当前高危条目已有跟踪，先让报告和预警对每个 PR 可见。提高阻断级别前，复核上游修复和项目可达性。浏览器任务保留 macOS 字体与桌面开发环境的验收条件。

## 查询及进程边界

会话查找在单次同步调用内复用已验证的工作区目录观察和一份目录索引。仍检查重复会话身份、目录重叠、缺失目录和持久化清单。写入仍在各自锁内复核。不在请求间缓存目录事实，移动、释放或外部变更可以在下一次读取中观察。若用户规模超出本次 30 工作区基线，先测内存索引的失效成本及跨进程一致性，再决定是否增加持久索引。

Pi stdin 已积压或单实例有 200 个待回执请求时，新命令明确拒绝于写入之前。现有待回执请求沿用确认、超时和关闭流程。使用终端测试确认饱和时无新写入，排空后可重试，避免引入独立写队列及第二次缓冲。后续依据待回执峰值和饱和诊断调整阈值。HTTP 记录慢请求和服务端错误的操作模板及耗时，作业失败保留运行实例和作业标识、故障码及耗时。

Canvas 投影依赖已提交的历史和工具执行结果。文本流的未提交状态与按键反馈复用已有投影。仿真以会话和 Run 持有独立资源生命周期，时间块按发布哈希缓存。后续需要增量投影时，先测真实长历史中含大体量 Geo／视频成果的情况。
