## 1. 首期目标

面向交通分析人员，完成一条可核查的路径：

**登记固定版本与证据 → 正文引用 → 详情核对 → Canvas 定位 → 复制和报告保留依据。**

必须保留：引用区整体默认折叠；原文与知识归纳分开；同一结论可以关联多个原文位置；数据结果可读；已选知识/数据资产按目录逐层披露；版本、授权与失效检查；Host 重启后仍可查看；各出口不丢失具体定位。

引用不以生成专门 JSON 为前置条件：已有原件或结果文件直接登记，小型瞬时结果由受控服务内部保存。内部存储可使用 JSON，用户无需为每项结论额外导出文件。

## 2. 职责边界

| 模块 | 首期负责 | 不随本次升级扩展 |
|---|---|---|
| 知识 Module | 自身轻量目录索引、按需检索、原件位置、知识归纳及全部出处 | 通用导入器、全平台索引构建、法规适用性自动判断 |
| 数据/分析 Module 或服务 | 自身数据集/表目录与 Schema 的按需发现；执行查询计算，产生结果、字段说明及实际已有的运行记录 | 通用 SQL 服务、拦截任意 Python/Bash、统一可复现环境 |
| Citation | 登记来源版本和证据、受控读取、正文标记解析、依据详情与导出 | 搜索全库、执行计算、维护独立 Claim/来源图或使用状态机 |
| Canvas | 打开受控完整资料，按已有领域能力定位和复用标签 | 新选区编辑、Context 自动转证据、通用 Evidence Viewer |

Node Host 负责授权和持久化，Kernel 提供命令，React 负责交互。Citation 不依赖 Canvas 才能成立；Canvas 继续可查看没有引用的普通文件。

知识和数据可以采用不同物理布局。它们向 Citation 提供统一的受限来源/定位输入，不必实现统一检索算法或五方法 Provider 接口。初期用现有服务中的少量适配函数，不建立可执行插件注册体系。

**最小渐进披露**：会话初始化只提供已选资产 ID、简短用途和现有浏览/检索入口，不载入全量正文、知识条目或表记录。随后由 Module 自身的 Skill/脚本按需提供：有界目录（专题、文档、数据集或表）→ 有限候选与摘要 → 指定原文片段或结果。目录/候选必须分页或显式截断，并保留可继续解析的来源定位；简单单文件附件无需目录。

目录索引由 Module 提供，Citation 不构建或扫描整库。验收至少覆盖一个多文档知识资产、一个多数据表资产，确认启动只给概览、后续逐层读取；样本未提供时记录待验收，不能以 mock 或空资产冒充真实验证。

## 3. 最小数据模型

### 3.1 只持久化两类记录

| 记录 | 必要内容 | 存在理由 |
|---|---|---|
| SourceVersion（来源版本） | sourceVersionId、逻辑来源键、标题、受控内容引用、Host 计算的内容摘要、必要的来源元数据 | 固定被引用内容，并供多处证据复用 |
| Evidence（证据定位） | evidenceId、sourceVersionId、类型化定位、内容性质、可选有界片段 | 指明支持当前表述的页、章节、行列或结果字段 |

逻辑来源键只用于辨识出处，可由已选资产 ID + 原件相对位置，或会话文件/受控执行身份确定，不增加独立 Source 表。一个来源内容变化后产生新的 SourceVersion，不原地改写历史版本。

同名文件、相同字节不必是同一出处；去重同时考虑授权来源、内容摘要和定位。同一版本被多次引用不复制内容。一份统计 CSV 即使同时是数据、计算输出和交付成果，也只登记同一份来源版本；成果卡继续由既有交付入口表达，不增加 artifact/result 类型来重复登记。

真实上游和运行信息有则记录：SourceVersion 可带受控 executionRef 和输入版本/哈希引用，直接复用现有 manifest。没有执行记录时不补写“已记录执行过程”。不另建 Provenance 实体、图管理或 Receipt 数据库。

### 3.2 两种内容保存方式

- **受控文件**：会话内文件或当前计划已授权资产中的原件/结果，记录授权域、受控路径、MIME 和哈希；继续使用真实路径与内容检查。
- **有界内联内容**：仅由 Host 受控生产者固定的小型结果，保存规范化内容及其摘要；不伪造文件路径。服务已落盘的结果/manifest 按受控文件读取，无需第三种通用存储驱动。

稳定来源直接引用，不复制整库。需要长期核对且内容会被覆盖时保存最小必要快照；若没有保留旧内容，明确返回原版本不可用，不能改读当前文件。普通工作区浏览继续查看最新文件，与固定版本引用分开。

### 3.3 定位与内容性质

首期定位仅覆盖实际验收需要的四类：文档页/章节或可靠段落锚点、表格行列/单元格、受控结果字段、整份来源。行号从 1 开始且不含表头；定位必须对应固定版本。超出 Viewer 能力时显示真实降级范围，不把打开整份文件称为精确定位。

内容性质只区分原文片段、知识归纳、数据结果和仅有出处。知识卡 statement 默认是归纳；模型综合判断留在回答正文，不自动创建知识实体。归纳说明由知识 Module 提供，支持它的多个原件位置分别登记为 Evidence，通过同一正文标记一起引用，不只取首个出处。只有可从固定原件核对的片段才能显示“原文摘录”；PDF 没有可靠文本时可定位原页，不新增 OCR 或自动抽取框架。

核验时间/已取得的核对事实可以保存；当前资源是否存在、权限和可读取状态在请求时检查，不建设多维状态机。领域审核与法规适用信息由 Module 有则提供，没有就不宣称已验证。

## 4. 来源登记与正文引用

### 4.1 单一步骤登记证据

收敛到一个登记工具，可沿用 `tau_resolve_citation` 名称，接收：

- 会话文件引用，或当前已选资产 ID + 原件相对位置；
- 有界、类型化定位，以及必要的来源说明；
- 受控服务已经登记的结果身份。

Host 解析授权域、真实位置和内容摘要，复用/创建 SourceVersion 与 Evidence，返回本次 evidenceId 和简短预览，不返回累计 Registry。调用方填写的标题、版本、querySummary 只是说明，不能提升为实际执行事实。

删除固定知识目录/K-... 专用解析和 knowledgeIds 参数；不建设 Legacy Adapter。现有知识检索由对应 Module 调用其脚本，返回原始资料位置后使用上述登记入口。目录命中只是候选，必须进一步解析到授权范围内的具体原件/结果和稳定位置才能登记为 Evidence，目录摘要不能冒充原文。Citation 不再扫描 `_catalog/` 或知识卡文件；无需知识卡的原文也可登记。必要时只更新对应 Module 的出处输出，不要求重建整套知识平台。

内联结果只能由现有 Host 受控服务登记，通用 Agent 工具不能提交任意数值并标为受控计算结果。没有这种执行路径的查询，仍可直接引用已有真实输出文件，并说明执行记录缺失。

### 4.2 引用使用从正文派生

正文直接使用 `[[cite:evidenceId]]`；多依据使用 `[[cite:evidenceId1,evidenceId2]]`。复用现有多 ID 标记解析形状，替换其解析对象。

不再单独调用 `tau_cite` 创建 Citation 记录，不增加 citationId、准备/绑定/回填流程。消息和报告正文是引用使用位置的权威；显示编号、当前消息的 Evidence 集合和使用位置由解析/编译生成。输入区选择已有证据直接插入标记。

同一 Evidence 可以在不同消息、报告中复用；重复出现不复制内容。引用编号按当前回答/报告中来源版本的首次使用顺序生成，同一原件两个条款共享编号，但各自 Evidence 保留。同一标记多个来源可显示 `[1, 2]`，点击时保留该标记的全部定位。

首期不提供全会话精确“使用次数”后台；当前内容的数量可直接计算。今后确有每次使用的独立角色、批注或审计需求，再评估是否需要持久化 Citation。

## 5. Registry、读取与协议范围

继续使用会话内 `.tau/citations.json` 和现有原子写入机制，保存两类记录及有界内联内容，不新增数据库、全局缓存或同步增量协议。登记失败不得留下半套关联；列表与详情通过 Kernel 按 ID/分页读取，Host 持久化是权威，不能只依赖临时 toolResult。

新 Citation 使用唯一新协议（计划 `pi-citation` 3.0、Registry schemaVersion 2），Host、Extension、Kernel、React、报告编译器一次贯通。旧 Citation/旧知识包不做双读或自动迁移；发现旧 Registry/旧标记时明确不支持，不猜测 ID、不静默覆盖数据。重置如有需要限于明确指定的引用记录，不清理工作区、Canvas Context 或其他文件。

**首期不新增 Catalog 描述符，不升级 ResolvedSessionPlan 到 v4。** 沿用当前任务计划里的已选资产和授权根，Module 自身的目录索引/检索与运行时资产映射继续按现有机制工作。索引缺失、损坏或输出超限时明确报错或标明截断，不由 Citation 扫描整库补救。Citation 格式退出不改变普通会话恢复和全局计划版本；未来新增资产协议时另行评估。

只保留必要的容量限额作为具名常量：单个内联结果 256 KiB，Registry 总计 8 MiB，文本/表格预览原始读取 2 MiB、首屏最多 200 行。实现前以现有样本核对，调整必须记录依据。PDF/Office 完整查看沿用各自限制，不受文本预览上限替代。

限额应在读入/写入前生效；完整文件哈希可流式计算。超限、资源缺失、版本变化、未授权、格式不支持分别提示。不新增逐模型 Token 计数、分片索引或按多个实体数量计费的预算体系。

## 6. 首期交互与 Canvas

### 6.1 引用详情

- 引用依据整体默认折叠为一行，数量是当前消息中唯一 Evidence 数；异常仍有可见提示。
- 展开后以可读标题和具体位置为主，路径、资产 ID、技术版本进入详情，不重复“参考资料 / 1 条引用”。
- 正文编号、页尾、输入候选和已有引用管理入口复用同一详情分流；管理入口只同步适配，不新增资源图或管理功能。
- 只保留一个详情侧层，悬停只做短提示；无片段不弹大空浮层。多来源知识归纳显示全部原文依据，不能只取首项。
- CSV/规则 JSON 等结果按有界表格呈现，不规则内容提供安全文本或真实原文件入口。中文字段名和单位来自正式说明，不猜测业务含义。
- 会话切换取消请求，迟到结果不覆盖新内容。三主题消费 semantic token、功能文字至少 11px；支持键盘、Escape、焦点返回与窄视口内部滚动。

### 6.2 Canvas 只接正向查看与定位

路径为 **Evidence → 来源版本 → 已有 Viewer target**。Citation 负责版本和授权，Canvas 负责视图生命周期与领域导航；不合并两者的 Registry，不形成 Module 循环依赖。

优先复用既有 capability 资源引用，以 sourceVersionId 作为 Citation capability 的不可变资源句柄。当前 CanvasService 尚未接入这条读取路径，需增加窄的来源版本解析，并同步 Document/Office 的真实读取与类型投影，不能构造假的旧 CitationResource。

| 内容 | 首期行为 |
|---|---|
| PDF | 固定版本的物理页；不承诺逐字高亮或获取原生阅读器选区 |
| Markdown | 已有可靠标题/章节定位；无稳定段落锚点时明确定位到章节 |
| XLSX | 复用已有 Sheet/单元格导航，仅在确有对应关系时定位 |
| CSV | 补齐依据行范围到表格行的受限导航/标记，列作为相关字段提示，不扩建表格编辑器 |
| 内联小结果 | 在依据详情核对；不为进入 Canvas 另导出临时文档 |

同一会话、同一来源版本和 Adapter 复用标签，切换定位不重复开页，不同版本不互相覆盖；关闭标签不删除证据。用户点击与 Agent 呈现使用相同的版本解析/定位映射，用户操作不伪造 Agent toolResult。

保留已有 Canvas 显式附加功能，但不新增手动视图分享流程、Markdown/CSV 选区或 Context 转 Evidence。Canvas 的视图代次与来源内容版本分开；原有 Geo/Video、普通文件视图和历史处理不因本次引用改造被删除。

## 7. 复制、报告和一次受控试点

### 7.1 所有出口保留同一依据

共用标记解析与编号规则。书目按来源版本去重，精确位置按 Evidence 保留：同一文献两条条款、多原文知识归纳不能在复制/报告中缩成第一个定位。原文、归纳和结果标签一致，公开导出不写本机路径作为可访问链接。

复用现有 Markdown/PDF 与书目 Formatter，保留 GB/T、BibTeX/CSL-JSON/RIS 现有入口，不新增证据包/复现包。文档业务分类与文献格式类型分开；成果卡与引用详情可以引用同一来源版本，Citation 不决定是否交付成果。

### 7.2 只接一个自动执行记录生产者

以现有 [SpatialAnalysisService](../src/server/spatial-analysis-service.ts) 为唯一首期自动登记试点，复用已校验输入、参数、输出哈希和 manifest。来源版本上保存这些真实引用，必要的小型结果直接内联，不再生成专门证据文件。

分析失败/取消不登记成功结果；登记失败返回明确状态，保留已经成功生成的分析文件；重试同一执行幂等。注意不要让登记失败进入当前分析 catch 的输出清理路径。

普通数据验收引用真实已有查询输出，验证字段说明、版本与定位即可。三站统计可作为样本，不要求为引用升级新建数据查询服务，也不把查询说明当作实际 SQL 执行记录。生产数据 Module 的自动登记待生产者明确后再接入。

### 第一步：登记与读取

- [x] 落地来源版本/Evidence 契约、两种保存方式、唯一新协议和单步登记工具。

### 第二步：交互、Canvas 与导出闭环

- [x] 默认折叠、单一详情、有界表格和准确内容标签，统一全部现有引用入口。

验收：知识归纳可核查至少两份原件；同一原件两处引用各自定位；数据结果可直接核对；复制/报告保留全部依据；关闭 Canvas 后引用仍可读。

### 第三步：受控试点与回归

- [x] 接入空间分析的真实输出/manifest，覆盖成功、失败、取消、登记失败与重试。

验收：一个真实受控生产者无需另写证据文件即可形成依据；不存在累计 Registry 响应、重复内容或假执行记录。三步在同一功能分支贯通后交付，不为中间节点维持双协议。

## 9. 检查与改动边界

主要改动位置：[citation.ts](../src/contracts/citation.ts)、[citation-compiler.ts](../src/contracts/citation-compiler.ts)、[citation-service.ts](../src/server/citation-service.ts)、[citation-registry.ts](../src/server/citation-registry.ts)、[citation-resources.ts](../src/server/citation-resources.ts)、Citation Extension、Kernel commands、引用投影/组件、Canvas 文档读取与报告出口；空间分析仅增加现有执行结果登记接线。

需核查旧 ID/Envelope 消费者，尤其 Canvas Adapter、Document/Office、report-renderer 图片引用、输入候选、成果入口与 Session 的引用 Registry 关联。不用类型断言或假路径掩盖不匹配；不重构无关会话、Module 装配或文件浏览功能。

| 验收场景 | 关键检查 | 复用位置 |
|---|---|---|
| 一个原件多定位、多来源归纳 | 去重、原文/归纳标签、所有位置及导出一致 | citation-service.test.ts、citation-utils.test.ts |
| 多文档知识资产、多数据表资产的目录披露 | 初始化只给概览；目录/候选有界，按需读取片段/结果；目录命中不直接成为证据 | 现有 Module Skill 的只读真实资产验收及 Pi smoke |
