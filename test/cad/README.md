# CAD Stage 0 validation

This directory contains Stage 0 evidence plus the first CAD engine tests. It is not the production CAD Service.

## Engine

`modules/capabilities/cad/scripts/cad_engine.py`

```powershell
& "desktop\build\runtimes\python\python.exe" "modules\capabilities\cad\scripts\cad_engine.py" --health
& "desktop\build\runtimes\python\python.exe" "modules\capabilities\cad\scripts\cad_engine.py" --request "<jobDir>\request.json"
```

The engine:

- accepts a `tau-cad-engine` envelope with `action: draw | inspect | verify`;
- writes temporary DXF/PNG/PDF only under the job directory;
- never commits `cad/<fileId>/rN.dxf` itself — the Host Service owns revision locking and final commit;
- prints one JSON result on stdout, matching the CAD contracts.

Run engine tests:

```powershell
$env:PYTHONIOENCODING = "utf-8"
& "desktop\build\runtimes\python\python.exe" -m unittest discover -s test\cad -p "test_*.py"
```

It validates that the bundled Python runtime can:

- read WGS84 GeoJSON and project it to a metric CRS;
- create a DXF with explicit units, layers, closed boundaries and labels;
- reopen and audit the DXF;
- render readable PNG/PDF previews (including CJK text);
- detect open boundaries, zero-length geometry, duplicate geometry and missing units.

## Run

From the repository root, using the bundled runtime:

```powershell
$env:PYTHONIOENCODING = "utf-8"
& "desktop\build\runtimes\python\python.exe" "test\cad\stage0_validate.py"
```

Or inside a TransportX session, use the session Python:

```powershell
$env:PYTHONIOENCODING = "utf-8"
& $env:TAU_PYTHON_COMMAND "test\cad\stage0_validate.py"
```

Outputs are written to `test/cad/out/` and ignored by Git:

- `summary.md` / `summary.json`
- one `rN.dxf`, `rN.png`, `rN.pdf` per scenario
- `_negative_controls/` probes

| 01 | `01_centerline_buffer.geojson` | 中心线 + 3 m 缓冲 |
| 02 | `02_intersection.geojson` | 路口渠化 |
| 03 | `03_crosswalk_stopline.geojson` | 人行横道 + 停止线 |
| 04 | `04_signals.geojson` | 信号灯点位 + 标注 |
| 05 | `05_markings.geojson` | 实线 / 虚线 / 导流线 |
| 06 | `06_transit_stop.geojson` | 公交站点 + 站台 |
| 07 | `07_workzone_detour.geojson` | 施工围挡 + 绕行 |
| 08 | `08_layer_edit.geojson` | 多图层批量改层（生成 r1 后改 r2） |
| 09 | `09_existing_r2013.dxf` | 已有 DXF 移动实体（r1 → r2） |
| 10 | `10_units_missing.dxf` | 单位缺失的 DXF（期望 `cad.units` warning） |

`09` and `10` are generated by `make_dxf_fixtures.py`; rerun it only if the fixture contract changes:

```powershell
& "desktop\build\runtimes\python\python.exe" "test\cad\make_dxf_fixtures.py"
```

## Expected result

All scenarios should be `pass` except:

- `10_units_missing`: `expected-warning` (`$INSUNITS=0` plus `cad.units` warning).

All three negative controls must be detected:

- `open_boundary` → `fail` / `cad.open_boundary`
- `zero_length` → `fail` / `cad.degenerate`
- `duplicate_geometry` → `pass-with-warning` / `cad.duplicate`

## What this does not prove

- It does not prove the production `cad_inspect` / `cad_draw` / `cad_verify` tools exist; those start in PR #1.
- It does not prove the packaged app can load the script; that needs `preferUnpackedPath()` and the packaged smoke test.
- It does not prove engineering correctness; drawings are schematic and require engineer review.
