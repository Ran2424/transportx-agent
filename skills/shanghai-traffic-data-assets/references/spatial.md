# 空间数据与制图

## 坐标契约

- 公交、轨交标准点线字段统一为 WGS84，经纬度标签为 `EPSG:4326`。
- 高德原始点线为 GCJ-02；使用迭代逆转换生成标准WGS84，原始值保留在 `source_*` 字段或治理库。
- 官方公交站原始投影为 EPSG:32651；使用 `pyproj` 转为 EPSG:4326。
- 未知或混合CRS对象保持 `UNKNOWN`，不能因为数值落在上海经纬度范围就推断为WGS84。

## 按问题选择空间对象

| 问题 | 使用对象 |
|---|---|
| 统一轨交全网线路 | `metro.dim_metro_line.geometry_json` |
| 某一高德方向或支线路径 | `metro.dim_metro_route_direction.geometry_json` |
| 物理站点分布 | `metro.dim_metro_station.longitude/latitude` |
| 统一线路上的站点 | `metro.bridge_metro_line_station.longitude/latitude` |
| 高德方向线路站序 | `metro.bridge_metro_route_station` |
| 高德公交方向线路 | `bus.dim_bus_route_direction.geometry_json` |
| 公交线路/方向站序 | `bus.bridge_bus_line_stop` |
| 跨领域空间索引 | `common.dim_geo_feature`，并同时检查每行CRS |

换乘站可以有一个物理实体和多个线路上下文点。线路制图使用上下文点；实体去重、站点计数或客流连接使用物理 `station_id`。

## 距离与投影

- 存储和交换：EPSG:4326。
- 上海米制缓冲、最近邻和点线距离：EPSG:32651。
- Web瓦片叠加：EPSG:3857，仅用于显示，不作为高精度米制测量。
- 不在经纬度坐标上直接调用平面 `buffer` 或 `distance`。
- `haversine_km` 只用于两个兼容经纬度点；不要用于点到线距离或混合CRS对象。

标准点线距离是在WGS84对象投影到EPSG:32651后计算。最近构建中，1,200条轨交方向站序、532条统一线站关系和3,428条高德公交方向站序均没有超过25米的记录。

## 已知空间特征

- 420个轨交物理站中419个有WGS84坐标；严御路缺失，不绘制伪坐标。
- 上海体育馆站的4号线上下文点与物理站点重合；1号线上下文点距物理点约142米。该差异反映线路/站台上下文，不应自动判为错误。
- 11号线完整线路延伸至昆山；全网图保留完整线路时会超出上海行政边界。
- 同一高德公交 `stop_id` 在不同方向线路中可能返回不同坐标，必须保留关系粒度点位。

## GeoPandas制图流程

1. 从 `geometry_json` 构造EPSG:4326 GeoDataFrame。
2. 按分析目的投影到EPSG:32651或EPSG:3857。
3. 线路图叠加关系表中的上下文站点，不强制使用物理站质心。
4. 用低对比度底图；底图只提供道路、建筑和地名参照。
5. 标注数据快照、源CRS、标准CRS、绘图投影和站点口径。
6. 全网图优先导出PDF：线路、站点、文字和图例保持矢量；瓦片底图仍为栅格并保留署名。

全市尺度不适合标注所有站名。用站点圆点表达完整性，另做中心城区或目标区域放大页；不要通过加粗底图道路解决可读性问题。
